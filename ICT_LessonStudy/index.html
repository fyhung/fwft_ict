03 / 簡單資料庫示範

叉雞飯是零，
就真的不能供應嗎？

餐點接單後才組合，尚未裝盒。把庫存記在材料層次，再用配方判斷，便能回答舊表未能回答的問題。

試改材料庫存

每種材料的1份代表其固定用量。拖動數值，看看三款餐點有甚麼變化。

一份叉雞飯的配方
0.5份叉燒 ＋ 0.5份油雞 ＋ 1份白飯

只要有一種材料不足，便無法供應。預設庫存下，最多可做6份叉雞飯。

各款餐點的上限獨立計算，假設所有材料只用於製作該款餐點；這些上限不能相加。

SQL / 找出目前無法供應的菜式
SELECT DISTINCT D.DishID, D.DishName
FROM Dishes D
LEFT JOIN DishIngredients DI
    ON D.DishID = DI.DishID
LEFT JOIN Ingredients I
    ON DI.IngredientID = I.IngredientID
WHERE I.Stock < DI.RequiredQty;

以上展示查詢邏輯；上方小示範按配方在瀏覽器即時計算。

04 / 課堂研究

80分鐘，
觀察思考怎樣改變。

課堂採教師講授與全班對話，由單一投影 AI 支援。預先設定學習目標與關鍵問題，讓學生的理由影響每一輪的具體方向。

0–20 MIN情境與命名整理
20–40 MIN材料拆解與三表
40–58 MIN兩版 ER 圖
58–76 MINSQL 與反例驗證
76–80離堂票

SQL 精簡為四分題：缺貨材料2分、材料種類統計3分、叉雞飯配方3分、無法供應的菜式4分，共12分。

01

意見能否影響下一步？

記錄哪個學生建議成為修改指令，及教師如何根據理由選取測試。

02

能否用證據回應彼此？

觀察學生是否引用具體紀錄、提出反例，回應同學或 AI 的主張。

03

能否解釋為何修訂？

比較資料庫版本，配合個人 ER 草圖與離堂票，了解全班的理解。
